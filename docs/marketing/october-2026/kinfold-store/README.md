# Kinfold — six English App Store images per device

Six distinct benefits cover the family vault, copying typed document details,
travel logistics, packing by family member, appointments/renewals and local
search. The deliverable is **six iPhone and six native iPad images**, all in
English for owner review. This is a new Kinfold set using the approved studio
direction; approval of Giftly's pattern is not approval of this new copy/artwork.
No App Store upload or public product-page change is part of this pilot.

## Artwork

An original fictional-family airport photograph establishes the indigo/ivory
travel identity. Its prompt, original path and hash are in
`assets/provenance.json`. The first panel retains clearly visible family faces;
later panels use quieter photographic washes and a restrained flight path.
Large original Apple devices extend deliberately below the canvas. Panels 1, 3
and 5 are clean; panels 2, 4 and 6 emphasize complete, traceable native components.
No native text, buttons, document fields or hardware are generated by AI.

Editable `copy.json`, `layout.json` and `art.html` separate marketing copy,
device geometry, UI source rectangles and composition. Titles are 42px and
descriptions 19.5px at 390px; corresponding 320px previews retain 34.6px/16px.
Subsequent devices start 5.2% of canvas width below the measured copy bottom.
The hero leaves additional room for the people. Rounded masks remove neighboring
screen pixels around complete native copy-format rows, packing cards, result
rows and the iPad search field. Slight card rotations are editorial emphasis.

## Native capture provenance

Source: FamilyKit/Kinfold commit
`57a9c8b1b7dabae56ba71cb873160c863d4b8d64`. Archive it into a disposable source
directory, then apply `capture/fixture.patch`. The patch changes fictional
sample dates/events to upcoming October–December 2026 examples, translates
demo appointment titles into English, and makes the existing DEBUG navigation
hook select Lucas's fictional German passport. Its real demo scan retains
the existing **SPECIMEN** watermark. No app feature or UI layout is replaced.

Build the actual `FamilyVault` scheme in Debug for the iOS Simulator using a
task-owned DerivedData directory, `CODE_SIGNING_ALLOWED=NO` and the isolated
bundle `com.magiclabsolutions.FamilyVault.marketingcapture`. This task used
Xcode 27 and two owned iOS 26.5 simulators:

- iPhone 17 Pro Max, 1320 × 2868 native pixels.
- iPad Pro 13-inch (M5), 2064 × 2752 native pixels.

Use the existing DEBUG hooks recorded in `capture-iphone.json` and
`capture-ipad.json`. `FV_DEBUG_INMEMORY=1` creates a separate in-memory SwiftData
fixture. The existing `XCTestConfigurationFilePath` test-host guard prevents
live sharing/CloudKit background tasks from starting in this unsigned simulator.
It does not mount an XCTest runner or replace the app's views. Default 9:41,
full battery, English UI and dark appearance are recorded. The iPhone uses
Large system text; the iPad uses Extra Extra Extra Large via **native Dynamic
Type** to improve detail legibility. The main source checkout and user vault
are never changed. App executable and Debug dylib hashes are recorded together.

`scripts/marketing/kinfold-store-capture.py iphone` and `... ipad` install the
isolated app and capture six actual production screens plus the native date-copy
sheet used as foreground detail. The capture rejects an exited app before taking
a screenshot. IDs/default paths are task-owned; create new owned devices and
change those inputs when reproducing on another machine. Never reuse unrelated
booted devices or a production bundle's persisted data.

## Hardware and export

`frames.json` records original Apple PNGs, source URLs, asset hashes and measured
openings. Native screenshots fit uniformly into those openings. The iPhone
16 Pro Max hardware has the same 1320 × 2868 opening as this native phone capture;
the iPad hardware and capture both use the 13-inch M5 dimensions. Camera masks
come from the real hardware, without a second synthetic bezel.

Run `node scripts/marketing/kinfold-store-render.mjs` after captures are verified.
It exports 12 opaque RGB PNGs, validates exact dimensions/hashes, complete
foreground bounds, readable copy and measured spacing, then generates both
contact sheets and individual 390px/320px previews. `validation.json` records
every source crop and final layout. Inspect the previews visually in addition
to the geometry assertions.

Native masters and full exports stay local under ignored `native/` and
`exports/`; compact previews, original accepted assets, editable inputs and
provenance are versioned. The ZIP includes all 12 final PNGs, ordered by platform,
plus their checksum manifest. `index.html` reviews both complete sets.

Future localization must inventory actual supported app languages, translate
this editable copy and recapture the matching native UI. Do not relabel English
captures as translated deliverables. This package currently contains English
only, with no store upload, release submission or localization claim.
